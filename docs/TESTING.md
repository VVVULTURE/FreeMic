# Testing FreeMic

## Ground rules for every test

The tests were designed so they never disturb a computer that's in use:

- Nothing is played to physical speakers or headphones.
- The user's physical microphone is never opened. Tests use a synthetic
  microphone (null backend), a fake PulseAudio microphone, or VB-CABLE's
  virtual "CABLE Output".
- Default devices are never changed. No audio service is restarted on the
  host. Linux tests start their own private PulseAudio/PipeWire in a private
  runtime directory inside throwaway WSL test distributions.
- Windows tests that use VB-CABLE first check that **no application** has a
  session on `CABLE Output` and abort otherwise, so no program (e.g. Discord)
  can hear test tones.
- GUI windows are placed off-screen and never take focus (Windows), or run
  on a private Xvfb / headless Weston display (Linux). Key presses are only
  injected into the private Xvfb display.
- Linux GUI tests run one distribution at a time: WSL distributions share a
  network namespace, so two private X servers on the same display number
  would collide (seen once when two suites were started in parallel).

## 1. Automated tests (`cargo test --release`)

No audio devices are used. 55 tests, run on Windows, Debian 13, Arch (and by
`makepkg check()`):

| Suite | Tests |
|---|---|
| unit (25) | drift resampler: tracks ±1500/±300/0 ppm clocks without underruns, clean sine (SNR > 40 dB), underrun recovery, phase offset corrected without long slew, start-up surplus without pitch slew · limiter: never exceeds full scale, quiet signal untouched, transient caught by look-ahead · mixer: new sound waits until enough is queued · config: round trip + damaged-file recovery, unknown/missing fields, UTF-8 BOM, reorder · hotkeys: key mapping round trip · library: import/copy/replace/remove · `--play` lookup by name or button position · pad text contrast on every pad color · YouTube: single-video links recognized (watch, youtu.be, shorts, embed, live, music, nocookie, upper case), playlist/channel/search pages refused and `list=` reduced to the video, YT-Downloader's music queries, `ratio` equal to Python difflib (values computed with Python), music ranking equal to YT-Downloader's `score_music` run in Python, search output parsing (live streams dropped), `SHA2-256SUMS` parsing, error messages |
| formats (18) | WAV 8/16/24/32f-bit at 8–96 kHz mono/stereo, MP3 mono/stereo, OGG Vorbis, FLAC 16/24-bit, M4A AAC and ALAC: each decoded and resampled to 48 kHz, tones checked for level and SNR > 60 dB (lossless) · 5.1 downmix without clipping · 20 s file streams completely · probe info · empty/truncated/corrupt/not-audio files give errors, never panics · Ogg Opus reported as unsupported |
| UI layout (5) | see section 1b |
| pipeline (7) | real decoder thread + mixer + drifting simulated mic: play once ends by itself · loop repeats seamlessly · new sound replaces old within one period without a glitch · mic and sound mixed with independent gains · loud mic + loud sound never clip · unplayable file reports an error · a replacement isn't started before its own audio is queued · every period is checked for soundboard underruns |

Fixtures are generated by `tools/make_fixtures.sh` (ffmpeg).

Ignored by default (run with `-- --ignored`): `difflib_cases_from_python`
(3,000 generated string pairs, all equal to Python's
`difflib.SequenceMatcher.ratio`, including the 200+ character "autojunk"
case) and `youtube_live` (section 1c).

## 1b. UI layout (`tests/ui_layout.rs`)

The real UI code is rendered headless (an egui context without a window;
null audio; no global hotkeys) and every text shape and clickable widget is
collected from the output. Fails if two visible texts overlap (more than
2 px²), if a text is cut off at the side or reaches outside the window, if two
clickable controls overlap, or if a text half-covers a control.

- Soundboard, YouTube and Settings pages, dark and light, at 480×400,
  520×420, 600×460, 699×500, 700×500 (the bottom bar switches layout here),
  820×560, 1024×700, 1280×800 and 1920×1080, each at 100 % and 150 % scale,
  with the virtual mic working and missing (setup banner and instructions).
- A board with 14 sounds: long names, a 95-character name, one-letter and
  Japanese names, colors, loops, hotkeys.
- Playing a sound (play-once with a long name and a loop).
- An empty board.
- Rename dialog plus an error notification with a long file path.
- YouTube page: not set up (with an error), results with very long titles
  and channel names, downloading with progress, a long error, setting up.

It found and fixed during development: the scroll bar covering the last
column of buttons, a notification drawn over a dialog, the empty-board
message being cut off in small windows, the "playing" outline clipped at the
edge. **Result: 5/5** on Windows, Debian 13, Arch (0.6 s each).

## 1c. YouTube, live (`tests/youtube_live.rs`, needs the internet)

Installs yt-dlp into a temporary folder from GitHub (SHA-256 checked),
checks that a second call within 6 hours doesn't touch the file and a forced
check keeps the same version, searches (`me at the zoo`: 10 results, the
expected video among them), runs a ranked music search, looks up a video from
a link inside a mix (`&list=RD…`), downloads its audio (exactly one file,
`<id>.m4a`), decodes it with FreeMic's decoder (19.06 s, 44.1 kHz stereo),
and cancels a running search (stopped in 0.5–0.6 s, no yt-dlp process left).

**Result: passed** on Windows 11 (yt-dlp.exe 2026.10.26), Arch and Debian 12
(yt-dlp_linux 2026.10.26, glibc 2.36).

## 2. Windows end-to-end through VB-CABLE (`tools/windows/e2e.ps1`)

FreeMic (real WASAPI output to `CABLE Input`, synthetic 220 Hz mic) is driven
with `freemic --play/--stop` while `fmtest record "CABLE Output"` records the
virtual microphone in WASAPI shared mode, exactly like Discord would. The
recording is analyzed per second (Goertzel) for the mic tone (220 Hz), a
2 s "Beep" (440 Hz, play once) and a "Hum" (1 kHz, loop).

Checks (13): FreeMic opened the virtual cable · synthetic mic running ·
command pipe answers · before Beep: mic only · mic + Beep mixed · Beep ended
by itself · loop playing with mic · Beep replaced the loop · stopped, mic
continues · no clipping · exits on `--quit` · clean exit in the log · no
soundboard or mic underruns. It also measures CPU and memory, idle and
while playing.

**Result: 13/13** on Windows 11 Pro (build 26200), for the development
build, the **installed** copy (installer) and the **portable** zip build
(0.1.0), and again for the 0.2.0 build (redesigned UI).
Earlier runs: 12/12 ×4 before the underrun check was added. Level
accuracy: 220 Hz reads 0.250 for a 0.25 input; an LS-fit glitch scan found
no discontinuities (median residual −58 dB).

## 3. Windows microphone capture (`tools/windows/capture_test.ps1`)

FreeMic's real WASAPI capture code captures VB-CABLE's `CABLE Output` as
its "microphone" while `fmtest play "CABLE Input"` feeds a 330 Hz tone. The
mix goes to the null output (a WAV file). This tests capture, mono
conversion, and drift correction against a real device clock without the
user's physical microphone.

**Result: 6/6** (12 s: 11 full seconds at 0.298–0.300 for 0.30 input).
**5-minute soak (`-Seconds 300`): 6/6.** 299 of 300 s at 0.30 ± 0.02 (min
0.292, max 0.300), no clipping, no underruns, no skips. The drift controller's
correction averaged 5 ppm, momentarily −480…+575 ppm (≤ 0.06 %, under 1 cent),
and the mic buffer stayed between 1259 and 1823 frames (26–38 ms).

## 4. Windows installer and portable

`tools/windows/test_installer.ps1` (15 checks):
- A test build of the installer that pretends VB-CABLE is missing, with a
  stub instead of the download script: a **silent install doesn't start
  the VB-CABLE download** (no unexpected UAC prompt).
- The real installer, silently into %TEMP%: exit code 0, the installed exe
  is identical to the build, uninstall entry registered, Start menu
  shortcut, no desktop shortcut by default, `FreeMic.exe --version` works;
  silent uninstall: exit 0, folder, uninstall entry and Start menu removed.

`tools/windows/test_portable.ps1` (9 checks): `portable.txt` and the
VB-CABLE helper are included; FreeMic starts and quits over the command
pipe; settings and log are in `data\` next to the exe, which says
`portable: true`; nothing in `%APPDATA%`, `HKCU\Software` or the Run key.

Also checked by hand: the installed copy stores data in
`%APPDATA%\FreeMic`. Silent uninstall keeps it (by design); the interactive
uninstaller asks.

**Results: 15/15 and 9/9** (0.1.0 and 0.2.0). The 0.2.0 package also
contains `Inter-LICENSE.txt` (the font license).

## 5. Linux end-to-end (`tools/linux/e2e.sh pulseaudio|pipewire`)

Runs as an unprivileged user with a **private** sound server (PulseAudio
17, or PipeWire 1.6.10 + WirePlumber + pipewire-pulse) whose only devices
are null sinks and a fake microphone fed with a 220 Hz tone, plus a
private Xvfb display. `parecord` on `freemic_mic` acts as the receiving
application. 28 checks:

private server isolated · virtual microphone source exists · friendly
name "FreeMic Virtual Microphone" · default source unchanged · default sink
unchanged · FreeMic captures the (fake) physical mic · before Beep: mic only ·
mic + Beep mixed · Beep ended by itself · loop playing with mic · Beep
replaced loop · stopped, mic continues · no clipping · no soundboard or mic
underruns · **global hotkey** Ctrl+Shift+F9 starts a sound (X11, xdotool) ·
stop hotkey Ctrl+Shift+F10 stops it · screenshot · mic unplugged: no signal,
no crash · mic unplugged: no other source substituted · mic reconnected:
passthrough recovers · internal sink removed: **mix never re-routed to the
speakers** · virtual microphone re-created · sound server restarted:
virtual microphone back · FreeMic still running · `--quit` exits · virtual
devices removed on exit · settings saved · log written.

**Result: 28/28** on Debian 13 + PulseAudio 17 and on Arch + PipeWire 1.6.10
(many runs, including against the installed `.deb`, the installed Arch
package and the portable archive), and on Debian 12 + PulseAudio 16 (chroot);
again 28/28 everywhere with 0.2.0.

## 6. Wayland (`tools/linux/wayland_test.sh`)

Headless Weston 15 (GL renderer), no X server (`DISPLAY` unset), null
audio. Checks: FreeMic runs as a Wayland client · libwayland-client and EGL
loaded · screenshot shows the window · hotkeys reported as unavailable on
Wayland · quits cleanly. **Result: 7/7** on Arch (development build and
portable binary; 0.1.0 and 0.2.0). The Debian test distribution has no
Weston, so this test runs on Arch only.

## 6b. UI automation and persistence (`tools/linux/ui_test.sh`)

Private Xvfb display, null audio. Buttons get distinct colors so their
positions can be found in screenshots (ImageMagick), and xdotool drives the
mouse and keyboard on that display only. The null backend records FreeMic's
mix (the virtual-mic signal) to a WAV file for analysis. Checks: three
buttons found · **dragging** "Alpha" onto the third place reorders the board
and it's saved · **clicking** a button plays exactly that sound (660 Hz)
into the mix, and clicking it again stops it early (2 s of a 5 s sound) ·
**right-click → Rename…**, typing a new name and Enter saves it · dragging the
top-bar **Sounds** slider saves the new volume · after **restarting**
FreeMic: `freemic --play "Renamed Bravo"` finds the renamed sound, button #3
exists, the order is kept on screen, and the volume is still the changed
value.

With `--youtube` (needs the internet) it continues on the YouTube page, using
only clicks and typing in the window: **Set up YouTube downloads** installs
yt-dlp · a playlist link (`/playlist?list=…`) shows the error box and
downloads nothing · a link inside a mix is looked up as one result ·
**Add to soundboard** adds "Me at the zoo" · stored as
`sounds/youtube/jNQXAC9IVRw.m4a` · exactly one file downloaded · no yt-dlp
process left · `freemic --play "Me at the zoo"` plays it into the virtual
microphone (4–5 s above −40 dBFS RMS).

**Result: 12/12** (0.1.0) and **21/21** with `--youtube` (0.2.0) on Debian 13
and Arch.

## 8. Performance

Process CPU time over 10 s, measured by the e2e scripts (20 logical cores):

| | idle, mic passthrough on | playing a looped sound | memory |
|---|---|---|---|
| Windows 11 (VB-CABLE, window off-screen), 0.1.0 | 0.02–0.08 % | 0.06–0.07 % | working set 93–99 MB, private ~118 MB |
| Windows 11, 0.2.0 | 0.047 % | 0.047 % | working set 99–103 MB, private 122–126 MB |
| Debian 13 (Xvfb, Mesa llvmpipe), 0.1.0 / 0.2.0 | 0.04 % / 0.040 % | 0.34 % / 0.35–0.38 % | RSS 117 / 119.5 MB |
| Arch (Xvfb, Mesa llvmpipe), 0.1.0 / 0.2.0 | 0.03 % / 0.045 % | 0.11 % / 0.110 % | RSS 154 / 153 MB |

Download sizes (including documentation), 0.1.0 → 0.2.0: installer 5.1 →
6.5 MB, Windows portable zip 3.7 → 5.4 MB, `.deb` 3.4 → 4.7 MB, Linux
portable 4.6 → 6.3 MB. The increase is the embedded Inter font (0.9 MB) and
HTTPS support (rustls). yt-dlp is not included; it is downloaded on first
use of the YouTube page (23.6 MB `yt-dlp.exe`, 41.2 MB `yt-dlp_linux`).

During this work a real slowdown was found and fixed: the Settings page
looked for a JavaScript runtime on every frame, which searched every `PATH`
folder (slow on WSL, where `PATH` includes Windows folders). It is now
looked up once.

## 9. Not tested, and why

| Item | Reason |
|---|---|
| Your physical microphone (Logitech G432) through FreeMic | Needs permission to open a real device. The capture code path is tested with VB-CABLE's virtual capture device (section 3) and the Linux fake mic. |
| A real Discord/game call | Would inject audio into an application in use. `fmtest record` is the same WASAPI shared-mode capture that apps use. |
| Global hotkeys on Windows | Testing them means injecting key presses into the real desktop session. Tested on Linux/X11. The Windows code is the same `global-hotkey` crate path (RegisterHotKey). |
| Unplugging a device on Windows | Needs a physical replug or disabling a device (admin, system change). Tested on Linux. |
| Installing/removing VB-CABLE, interactive installer wizard, UAC flow | Driver installation needs permission. The download + signature check was tested (`install-vbcable.ps1 -VerifyOnly`); the silent path was tested to never start it. |
| "Start when I sign in" toggle | Would modify the user's startup entries. Implemented for HKCU Run and `~/.config/autostart`; the uninstaller's cleanup of the Run value is defined in the installer script. |
| Windows 10, Ubuntu, other distributions, HiDPI/multi-monitor | Not available here. (UI layout is tested at 150 % scale headless.) |
| YouTube page driven by mouse and keyboard on Windows | Would inject input into your desktop. Covered by: the Linux GUI test (same UI code), `youtube_live` on Windows, and a Windows screenshot of the page with a live search (started with `FREEMIC_TEST_YT_SEARCH`). |
| yt-dlp being replaced by a newer release | No newer release appeared during testing; the "same version" path and a fresh install were tested. A checksum mismatch can't be produced against the real GitHub; the comparison is a plain string check after hashing. |
